# 3-4 → 3-5 (panel del editor) — el núcleo está en pie: store, undo, autoguardado y lienzo

## 1. El store — `import { useEditorStore } from "@/lib/store"`
**Las acciones de edición son EXACTAMENTE las 11 operaciones de `@invitaciones/schema`**, con la firma
de la operación: `setBlock(blockId, value)` · `clearBlock(blockId)` ·
`addItem(groupId, values, index?) → tempId` · `removeItem(groupId, itemId)` ·
`moveItem(groupId, itemId, toIndex)` · `setItemBlock(groupId, itemId, blockId, value)` ·
`clearItemBlock(groupId, itemId, blockId)` · `setSectionVisible(sectionKey, visible)` ·
`setSectionVariant(sectionKey, variant)` · `reorderSections(order)` · `setTheme({paletteId?,fontSetId?})`.
Cada una hace sola las cinco fases de `04 §10.3` (valida, parchea `composed`, empuja la inversa
correcta, encola, programa el guardado). **No añadas una duodécima.**
Interfaz (sin operación): `select(ref|null)` · `scrollToSection(key)` · `openPanel` · `setViewport` ·
`previewTheme` · `pushWarning` · `dismissWarning` · `enterReadonly` · `setTabRole`.
Ciclo de vida: `load` · `chooseTemplateFor` · `restoreFromHistory` · `applyServerState` · `flushNow` ·
`resolveConflict` · `restoreRecovered` · `saveOnHide` · `hasUnsaved` · `attachCanvas`.
Selectores: `useSectionRows` · `useActiveBlock` · `useGroupItems` · `useIsDefault` · `useCanPublish` ·
`useSaveLabel` · `useUndoRedoLabels`. ⚠ **Nunca hagas `.map()` dentro de un selector con `useShallow`**:
bucle infinito de render (React #185, medido); selecciona la referencia estable y deriva con `useMemo`.

## 2. Cómo engancha un formulario del panel
```tsx
const bloque = useActiveBlock();                  // ComposedBlock | ComposedGroup | null
const sel = useEditorStore((s) => s.selection);   // BlockRef activo
useEditorStore.getState().setBlock(sel.blockId, { kind: "text", value });   // al escribir
useEditorStore.getState().setItemBlock(sel.blockId, sel.itemId!, sel.itemBlockId!, valor); // en grupo
```
Un clic en el lienzo ya deja `selection` puesta y `panel === "block"` (`04 §4`: **el panel abre ese
campo con el foco**; el lienzo no edita texto sobre sí mismo — nada de `contenteditable`). Solo falta
enfocar el `<input>` al cambiar `selection`. Los bloques con `refKey(ref) ∈ pendingBlocks` van con
`aria-busy` (§12.4).

## 3. Autoguardado y conflicto — ya enganchados, no los repliques
Toda acción encola sola: texto ⇒ debounce 2 s con `maxWait` 10 s; el resto ⇒ inmediato. Se observa con
`useEditorStore(s => s.saveState)` (`idle|dirty|saving|retrying|offline|conflict|error`) y con
`<SaveIndicator/>`, ya montado. `flushNow()` solo para Ctrl+S. `<ConflictDialog/>` (tres opciones, sin
rebase automático) y el candado de pestaña también están montados.

## 4. El puente del lienzo
`<CanvasFrame/>` es el único que crea el puente y registra el `CanvasSink` con `attachCanvas`. Háblale
al lienzo por acciones del store (`select`, `scrollToSection`, `setViewport`, `previewTheme`), **nunca**
con `postMessage` directo. Si no arranca tras dos intentos degrada solo a `/preview/[invitationId]`.

## 6. Lo que te va a doler, y no es culpa tuya
**Ninguna de las 19 rutas devuelve el `TemplateManifest`.** Sin él no hay `BlockSpec` para el resolver
de `react-hook-form` (`04 §10.2` lo daba por hecho), ni `SectionSpec.required` para ocultar el
interruptor de una sección obligatoria (`04 §7.1` paso 9), ni `ChoiceSpec.options`, ni `theme.json`
para el selector de paleta. Verificado por HTTP: ocultar `cover` responde `422 TPL_OPERATION_INVALID`
/ `TPL_SECTION_REQUIRED`. Pregunta abierta 1 (**ALTA**) y ADR-3-4-02. **No lo resuelvas duplicando el
manifiesto en el frontend**: sería exactamente H-27.

## 7. Dos cosas que no puedes romper
- **Cero `style={{…}}` en el árbol del lienzo** y **no vuelvas a crear `app/layout.tsx`**: anida los
  tres layouts raíz y el lienzo deja de arrancar (`bitacora/3-4.md §3`, ADR-3-4-01).
- **La inversa de `setBlock` sobre un bloque `default` es `clearBlock`** (ADR-1R-F-04, U-09). Verla
  como `setBlock(valorPorDefecto)` sería H-03 reabierto.
