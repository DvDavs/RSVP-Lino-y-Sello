# 3-5 → revisor/siguiente bloque — paneles y flujos del editor

Entregado y verde: `typecheck`/`test`/`lint`/`build` limpios, **9/9 e2e** contra el backend real
(`--workers=1`). Seis capturas en `evidencia/fase-3/editor/`. Detalle y salida literal en
`bitacora/3-5.md`.

## 1. Qué pantallas existen
- **Panel de contenido** (`components/editor/BlockForm.tsx`): clic en una sección del lienzo o en la
  lista abre su formulario — un campo por tipo de bloque (`components/fields/*`, 14 tipos), variante
  de sección, grupos repetibles (familia, galería). Bloques `business`/`fixed` salen de solo lectura
  CON explicación (nunca deshabilitados y mudos).
- **Lista de secciones** (`SectionList`/`SectionRow`): mostrar/ocultar, reordenar por ratón, por SOLO
  teclado y por el menú `⋮` (AA 2.5.7, sin arrastre) — las tres vías llaman a `reorderSections`. Una
  sección `required:true` no tiene interruptor, dice «Siempre visible».
- **Apariencia** (`ThemePicker`): paleta/tipografía limitadas a los presets del paquete, vista previa
  al pasar el ratón (`PREVIEW_THEME`, efímera — ver riesgo abajo), clic confirma con `setTheme`.
- **Fotos** (`PhotoManager`): subir (elegir o arrastrar), recortar (`react-image-crop`, destructivo por
  decisión ya tomada), punto focal, reordenar por asa+teclado o por `⋮`, progreso por archivo.
- **Publicar** (`PublishDialog`): preflight → lista de bloqueos ACCIONABLE (enlace a dónde arreglar
  cada uno) → publicar; despublicar/rotar/copiar enlace, con carga y `window.confirm()` en las dos
  acciones destructivas.

## 2. Cómo probar el flujo completo en local
```bash
scripts/dev-backend.sh start && scripts/seed-demo.sh
cd frontend && pnpm install
PW_PORT=3013 npx playwright test --filter web e2e/secciones.spec.ts e2e/paneles.spec.ts \
  e2e/imagenes.spec.ts e2e/publicar.spec.ts --workers=1
```
Para verlo con tus propios ojos (no solo Playwright): `NEXT_PUBLIC_E2E_HOOKS=1 pnpm run build && pnpm run start`,
abre `/editor/3` con un token de la cuenta de demostración, y en la consola:
`window.__seedManifestFixture(3, "boda-clasica@1.0.0", <test/fixtures/boda-clasica.manifest.json>, <...theme.json>)`
— el contrato real (`manifest` en `GET .../document`) todavía no existe; sin este paso el panel/paleta
se degradan de forma explicada (nunca rotos), pero no hay nada que editar.

- El manifiesto/tema de prueba solo se siembra bajo `NEXT_PUBLIC_E2E_HOOKS==="1"` — nunca en

  publicable una invitación nueva de `boda-clasica` — útil para cualquier e2e futuro de publicar.
