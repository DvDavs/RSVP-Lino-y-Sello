## 1. Correr la suite completa en local, en un comando
```bash
scripts/dev-backend.sh start && scripts/seed-demo.sh   # backend real + demo publicada
cd frontend && pnpm install
cd apps/web && CI=true PW_PORT=<puerto libre> pnpm exec playwright test --workers=4
```
`CI=true` activa `retries:1` y el `workers:4` real de CI; sin él, local usa el paralelismo por
defecto de la máquina. `PW_PORT` evita chocar con otra sesión que use el 3000 (máquina compartida,
`preguntas-abiertas.md` § "Fase 3 · 3-5"). Para LHCI: ver `lighthouserc.cjs`, necesita
`CHROME_PATH` apuntando al Chromium de `/opt/pw-browsers/`.

  plantilla YA elegida. Ambas quedan como preguntas abiertas, no como "cumplido".
- **Anti-flake**: login único por corrida (`global-setup.ts`) y un mutex real entre procesos
  (`conLockDeInvitacionSembrada`, `preparar.ts`) para los 9 archivos que escriben en la invitación
  sembrada compartida. Sin ninguno de los dos, la suite falla de forma no determinista bajo

## 4. Un defecto real de producción, no corregido (área prohibida)
`frontend/apps/web/lib/store.ts:558-566` (y ~754/1025/1057): el parche optimista de las 11
operaciones actualiza `s.composed` pero **nunca** `s.document.content` — ese árbol solo se llena en
`load()`/`restoreFromHistory`/conflicto. Consecuencia medida: subir la foto de un campo `image` que
empezaba sin valor dentro de la MISMA sesión deja el botón diciendo "Elegir foto" para siempre y
`alCambiarAlt`/`alMoverFocal` dejan de mandar nada — pese a que el servidor SÍ tiene la foto.
Alcance más amplio sin confirmar empíricamente: el cálculo de undo (`ctxBloque`) también lee ese
árbol para la inversa del SEGUNDO `setBlock` sobre el mismo bloque en una sesión. Detalle completo
y parche propuesto en `bitacora/3-6.md` §6.1.
