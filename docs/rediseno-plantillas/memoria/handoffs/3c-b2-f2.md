## API pública (`import { … } from "@invitaciones/ui"`)

- `Card` — `variant: "plana"|"elevada"|"color"|"tinta"`, `tone: "support-1"|"support-2"|"accent"`,
  `as`. `color` envuelve en `ColorShadow` de `shapes`.
- `Tabs`, `TabsList`, `TabsTrigger`, `TabsContent` — activación **manual** por defecto.
- `Dialog`, `DialogTrigger`, `DialogClose` — props `title`/`description` OBLIGATORIAS,
  `descriptionHidden`, `busy` (bloquea Esc/clic-fuera), `trigger`, `footer`.
- `Sheet`, `SheetTrigger`, `SheetClose` — mismo contrato que `Dialog`, hoja inferior con asa y
  `footer` pegado abajo (`safe-area-inset`).
- `Tooltip` — `content`, `children` (un elemento enfocable), `side`, `align`, `delayDuration=400`.
- `Toaster` (móntalo UNA vez), `toast(opciones)`, `useToast()` — cola con tope de 2 (`store.ts`,
  `TOPE_COLA`), región propia `role="status"`/`aria-live="polite"` además de la de Radix.
- `Badge` — `tone: "neutro"|"primary"|"success"|"warning"|"danger"|"info"|"accent"`.
- `Avatar` — `nombre` (iniciales), `src?`, `size: "sm"|"md"`, `estado?: "activo"|"ausente"`.
- `Breadcrumb` — `items: {label, href?}[]`; se oculta bajo `lg` (`hidden lg:block`).
- `WizardProgress` — **es** el «Stepper» de pasos de `11 §5` (renombrado para no chocar con el
  numérico); `pasos: {id, etiqueta, estado, href?}[]`, pinta «Paso N de M».
- `Stepper` — contador numérico NUEVO (no está en el doc 11): `value`, `onChange`, `min`, `max`,
  `step`, `label` (nombra los botones «Restar/Sumar `<label>`»), botones 44×44.
- `ProgressRing` — `value`, `max=100`, `label`, `indeterminate?`, `size=72`; el número siempre va
  como texto (completo muestra un check, `aria-valuetext` sigue diciendo el %).

## Cómo se consume

Igual que el resto del paquete: `import { Card, Dialog, toast, Toaster, … } from "@invitaciones/ui"`.
`Toaster` se monta una vez (p. ej. en el layout del chrome); `toast()`/`useToast()` funcionan desde
cualquier sitio en cuanto está montado.

## Dos comportamientos de Radix a tener en cuenta (no son bugs de este paquete)

1. **`Dialog`/`Sheet` devuelven el foco al nodo de la prop `trigger`**, no a "lo último enfocado". Si
   abres el diálogo por `open`/`onOpenChange` desde un botón que NO pasaste por `trigger`, el foco no
   vuelve a ningún sitio al cerrar — pásalo siempre por `trigger`, o gestiona el foco a mano si el
   diálogo se abre por otra vía (p. ej. tras guardar).
2. **`aria-modal` se fija a mano** en ambos: `@radix-ui/react-dialog@1.1.23` no lo escribe solo.

## Qué falta / fuera de este bloque

- Movimiento de entrada (`dur-3`/`ease-out`) de `Dialog`/`Sheet`/`Toast`: NO implementado (necesita
  `forceMount` + orquestación de salida; fuera de presupuesto). Hoy aparecen/desaparecen sin
  transición — cumple `prefers-reduced-motion` trivialmente.
- Galería `/design/componentes` (F3), formularios (`Button`, `Input`, `Select`… — F1).
