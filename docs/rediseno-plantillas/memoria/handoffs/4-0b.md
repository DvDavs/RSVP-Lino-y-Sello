# 4-0B → agente del CLI del kit de autor

Ya en el árbol (`wip/f4-0b`), en verde y con pruebas. **Es tu vocabulario: no vuelvas a leer `blocks.ts` ni `registry-data.ts` para saber qué roles o variantes existen.**

## Superficie pública
**`@invitaciones/sections/catalog`** (entrada propia; fichero `packages/sections/catalog/index.ts`.
La raíz del paquete NO carga en Node: arrastra `.tsx` y CSS):
- `sectionCatalog: Readonly<Record<SectionType, CatalogSection>>` — las 12 secciones, JSON puro (27,7 KB).
- `CATALOG_SECTION_TYPES` · `describeSection(type): CatalogSection | undefined`
- `scaffoldSlots(type): readonly CatalogSlot[]` — huecos del andamio (siempre ≥ 1).
- `blockIdFor(sectionKey, slot): string` → `"cover.title"` · `slotForRole(type, role)` (mira dentro de grupos).
- `CatalogSection {type,name,purpose,cardinality:"1"|"0..n"|"1..n",variants:{id,label}[],defaultVariant,slots}`
- `CatalogSlot {blockId,type,role,required,scaffold,singletonRole,purpose,itemBlocks?,min?,max?,itemLabel?,source?,businessField?}`
  (`required` va tal cual a `BlockSpec.required`; `scaffold` = lo escribe `nueva-plantilla`).

**`@invitaciones/schema`** (raíz; `packages/schema/src/introspect.ts`):
- `describeBlockType(type): BlockTypeInfo {type,summary,spec,value,roles,minimalSpec,minimalValue}` — lanza con sugerencia si el tipo no existe.
- `spec`/`value`: `BranchShape {required[],withDefault[],optional[],all[],fields[]}` — la forma exacta de la rama del `oneOf`, derivada de Zod.
- `ShapeField {name,type,required,hasDefault,defaultValue?,enumValues?,literal?,constraints?,fields?,element?,unionOf?}`
- `describeBlockTypes()` · `describeField(name, zodSchema)` (vale para cualquier esquema).
- `describeRole(role): RoleInfo {role,description,scope,singleton,blockTypes[],sectionTypes[]} | undefined` · `describeRoles()` · `rolesForSectionType(t)`.
- `explainBlockSpec(raw): {declaredType,known,missing[],unknown[],omittedWithDefault[],suggestions{type?,role?},message}`
- `suggestClosest(input,candidates,limit=3)` · `suggestRole` · `suggestBlockType` · `suggestSectionType`
- `BLOCK_TYPES` · `ROLES` (90) · `SECTION_TYPES` · `BLOCK_TYPE_TEXT` · `ROLE_TEXT_KEYS`

## Ejemplo copiable (Node 22)
```js
const { sectionCatalog, scaffoldSlots, blockIdFor } = await import("@invitaciones/sections/catalog");
const { describeBlockType, explainBlockSpec, suggestRole } = await import("@invitaciones/schema");

sectionCatalog.event.variants.map(v => `${v.id} (${v.label})`); // timeline (Línea de tiempo), cards, single-place
scaffoldSlots("event").map(h => blockIdFor("event", h));        // ["event.heading","event.cards"]
describeBlockType("group").spec.required;   // ["id","role","label","type","itemLabel","itemBlocks"]
describeBlockType("group").spec.withDefault;// ["required","editable","source","aiEditable","min","max","reorderable"]
describeBlockType("group").minimalSpec;     // BlockSpec mínimo que YA pasa BlockSpec.parse
explainBlockSpec({ id:"e.m", type:"group", role:"eventCards", label:{"es-MX":"M"}, constraints:{} }).message;
// 'bloque `type: "group"`. Faltan: itemLabel, itemBlocks. No admite: constraints (esta rama admite …).'
suggestRole("celebrantName");               // ["celebrantA", …]
```

## Reglas que heredas
1. **No re-exportes el catálogo desde `packages/sections/src/index.ts`**: un import de VALOR de
   `@invitaciones/schema` en `src/**` mete 87,8 KB gz de Zod en el render público y una guarda
   (`test/lint-guards.test.ts`) se pone roja. Ver ADR-4-0B-01.
2. El andamio ya está probado de punta a punta en `packages/sections/test/kit-scaffold.test.ts`
   (5 secciones, 10 bloques, `TemplateManifest.parse` + `validateManifest` = 0 violaciones, a la
   primera): **cópialo**. Genera cada bloque desde `describeBlockType(type).spec.required` y **lanza**
   si aparece un campo obligatorio que no sabes rellenar — así un cambio del esquema rompe el CLI en
   vez de producir un `template.json` inválido.
3. `theme.json`, `defaults.json` y los assets (`sha256`, `bytes`, `previewImage`) son tuyos: no están
   en el catálogo. La forma de `AssetEntry` sale de `describeField("m", TemplateManifest)`.
4. El esquema **no** valida rol ↔ tipo de sección (solo I-25/I-26): la plantilla de
   `evidencia/fase-3/i08-…` se registró con un grupo de `event` con `role:"familyGroup"` y una
   variante `portrait` inexistente. `RoleInfo.sectionTypes` y `sectionCatalog[t]` sí lo saben: es el
   aviso que tu `--check` puede dar y el registro no.
