## Comandos (desde `frontend/`; `pnpm plantilla` sin nada imprime esto mismo)
```
pnpm plantilla nueva <slug> --evento <tipo> [--secciones a,b,c] [--destino <dir>] [--version <semver>]
                            [--nombre <texto>] [--descripcion <texto>]
pnpm plantilla check <dir> [--no-escribir] [--estricto] [--silencioso]
pnpm plantilla registrar <dir> [--raiz <dir>] [--sin-check]
pnpm plantilla doctor
pnpm plantilla secciones [<tipo>]
pnpm plantilla preview <dir>      # HUECO 4-1B: src/preview.ts
pnpm plantilla capturas <dir>     # HUECO 4-1B: src/capturas.ts
```
`--evento` ∈ wedding, quince, baptism, communion, confirmation, birthday, graduation, generic;
`--secciones` por omisión `cover,celebrant,event,rsvp,footer` (los 12 tipos salen en la ayuda).
Salidas: `0` bien · `1` el paquete/entorno fallan · `2` error de uso. Las rutas relativas se resuelven
contra `INIT_CWD`, el directorio donde escribiste el comando, no contra el del paquete.

## Formato EXACTO de los mensajes (contrato: la guía lo cita y las pruebas lo comparan entero)
```
<SEVERIDAD> <CÓDIGO>  <fichero>#<puntero RFC 6901>
  <el problema, en una frase>
  Sugerencia: <qué escribir para arreglarlo, sin abrir código>
```
`ERROR` (no se registra) · `AVISO` (el registro lo acepta, pero probablemente no es lo que querías) ·
`CORREGIDO` (lo arregló el kit). Puntero `template.json#/sections/1/blocks/0/role`; `#$` = el fichero
entero. Hallazgos separados por una línea en blanco; última línea siempre `N error(es) · N aviso(s) ·
N corregido(s)`. Los cinco sabotajes literales, en `evidencia/fase-4/4-1a/check-sabotajes.txt`.
